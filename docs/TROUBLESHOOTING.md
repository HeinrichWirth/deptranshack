# Если что-то не запускается

**Страница не открывается.** Выполните `docker compose ps` и `docker compose logs --tail=80 inspector`. Адрес — http://localhost:8870. На Windows проверьте, что Docker Desktop запущен и выбран Linux container mode.

**Порт занят.** Измените левое число в `127.0.0.1:8870:8080` в `compose.yaml`, например на 8871, затем `docker compose up -d`. Откройте соответствующий адрес. Привязку к `127.0.0.1` оставьте: у локального приложения нет учётных записей для публикации в интернет.

**Большой файл загружается долго.** Загрузка идёт до начала расчёта; это копирование в Docker volume, не latency детектора. При первом запуске также скачиваются зависимости. На диске должно быть место для входа и сохранённых облаков; ориентируйтесь минимум на удвоенный размер bag, а для больших многотопиковых записей — больше.

**«Нет PointCloud2» или не хватает intensity.** Проверьте выбранный файл. Это должен быть SQLite `.db3` с CDR1 PointCloud2 и полями x/y/z/intensity. `.mcap`, `.db3.zstd` и metadata.yaml сами по себе не подходят. Сначала распакуйте архив.

**Облако повёрнуто, рельсы не находятся.** Ожидаемые оси: вперёд −Y, вправо +X, вверх +Z; метры; лидар в центре поезда. TF автоматически не применяется. Проверьте соглашение датчика.

**Срез закончился раньше 100 м.** Дальность ограничена принятым путём. При отказе C4 или недостаточной поддержке продолжения выберите более близкий срез или следующий расчёт. Отсутствие прогноза не означает, что участок свободен.

**Меньше трёх расчётов в секунду.** 3 Гц — частота запроса. При нагрузке регистрация и deadlines могут не позволить обработать каждое окно. В журнале есть `BATCH_UNAVAILABLE`, `GEOMETRY_ADMISSION_EXPIRED` и замены ожидающих кадров. Выделите Docker достаточно CPU и памяти; проверенная машина предоставляла контейнеру 32 логических CPU без квоты. Минимальные аппаратные требования на других CPU не квалифицированы. Начальная практическая конфигурация — 8+ CPU и 8+ ГБ памяти Docker, но это не обещание той же скорости.

**После остановки пропал расчёт.** Завершённые результаты сохраняются в named volume. Незавершённый прогон будет помечен как прерванный. `docker compose down -v` удаляет volume; обычный `down` — нет.

**Соседние предметы показаны одной строкой.** Группировка использует радиус 10 м от неподвижной опоры первого наблюдения. Близкие предметы могут объединяться; исходные ID и наблюдения доступны в JSON. Наблюдения дальше 10 м от опоры не присоединяются к этой группе.
