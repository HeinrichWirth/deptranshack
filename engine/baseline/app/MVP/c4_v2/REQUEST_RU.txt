# C4 V2 — FINAL PRODUCTION SPEED SOLUTION
# INCREMENTAL PERSISTENT TRACKER + FULL NATIVE CANDIDATE SOLVER
# NO MORE MICRO-OPTIMIZATION

Времени до сдачи почти нет.

Предыдущие performance-sprints показали предел
локальных оптимизаций старой архитектуры.

Текущий лучший equivalent backend:

native_batch_spatial

примерно:

full solve median ~1.1 s
C4 median ~0.88 s.

Это всё ещё слишком медленно.

При этом установлено:

- residual kernel уже ускорен кратно;
- FD Jacobian уже ускорен кратно;
- small-N NN уже ускорен;
- spatial cache уже есть;
- KDTree tricks проверены;
- Python threading не масштабируется;
- SciPy least_squares всё ещё вызывается тысячами;
- H8 batch остаётся частичным;
- Python/SciPy callbacks остаются;
- marching каждый раз в значительной мере
  реконструирует уже известную static geometry.

Поэтому больше НЕ делать
очередные H1/H2/H3 microoptimizations.

Нужна архитектурная версия C4 V2.

==================================================
0. ГЛАВНАЯ ЦЕЛЬ
==================================================

Получить production-oriented C4,
который поддерживает статическую геометрию пути
между последовательными кадрами.

Вместо:

FRAME T:
reconstruct 30–80m

FRAME T+1:
снова reconstruct 30–80m

FRAME T+2:
снова reconstruct 30–80m

+
validate overlap
+
extend / repair only tail.

То есть C4 становится:

PERSISTENT INCREMENTAL TRACKER.

==================================================

5. проверить overlap;
6. repair только небольшой tail window;
7. extend only missing horizon.
